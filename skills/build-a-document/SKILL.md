# Build a document

Never start writing immediately.

1. list every file in the brain that touches the subject
2. show me that list and wait — I will add what is missing
3. write the outline. one line per section
4. only then write the body, citing sources as you go

Step 2 is not optional. It is the step everybody deletes and the one that decides whether the document is any good. A document written from the wrong sources is worse than no document, because it reads as though it were researched.

If a claim has no source in my files, mark it TO CHECK. Do not quietly fill the gap from general knowledge — the point of this is that the document says what I know, not what the internet knows.

## Style

- Information density over length. If a sentence carries nothing, cut it.
- No "Last updated" line. Version control exists.
- Never repeat content that lives in another file. Link to it instead.

## Rendering is somebody else's job

Once the markdown is right, hand it off rather than formatting it here:

- a document → the `to-pdf` skill
- a presentation → the `dynamic-presentation` skill

Keep the markdown as the source of truth either way. The PDF and the deck are build artifacts, and you should be able to throw them away and regenerate them the day a number changes.
